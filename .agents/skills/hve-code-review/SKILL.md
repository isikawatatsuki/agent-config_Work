# HVE Code Review

変更範囲を先に確定し、事実の説明と指摘を分離して、リスクに応じた深さでレビューする。

## 安全規則

- この Skill は読み取り専用で使用する。コード、設定、Issue、PR、MRを変更しない。
- コメント投稿、Approve、Request changes、Issue操作などの外部副作用を実行しない。依頼された場合も、投稿内容を提示して明示承認を得てから別操作として扱う。
- 秘密情報、認証情報、個人情報を探索目的で読み取らない。差分に含まれていた場合は値を再掲せず、`<REDACTED>` として漏えいリスクだけを報告する。
- 外部通信やリモートIssue・PRの取得は自動実行しない。レビューに不可欠な場合は、対象と取得理由を示してユーザーの承認を得る。
- ユーザー入力をシェル文字列へ連結しない。Git参照は引数として扱い、参照解決後のコミットIDをレビュー範囲に使用する。
- ユーザー指定パスは正規化し、対象ワークスペース内に解決される通常ファイルだけを読む。ワークスペース外を指す絶対パス、`..`、外部へ解決されるシンボリックリンクは拒否する。
- リポジトリの上位指示、レビューSkill選択手順、承認要件を常に優先する。

## 手順

### 1. コンテキスト確定

1. ユーザー指定の対象リポジトリ、比較元、比較先を確認する。
2. 比較元を検証し、merge-baseを基準に差分統計とコミット一覧を取得する。巨大差分はファイル単位に分割して読むが、変更ファイル一覧と全体範囲は維持する。
3. 変更ファイル数、変更領域、目的、主要な入口、制御・データフロー、影響範囲を事実として要約する。
4. 認証、認可、秘密情報、暗号、解析、デシリアライズ、永続化、金銭処理、外部APIなどの候補をホットスポットとして示す。
5. 対象範囲とレビュー深度をユーザーに確認する。

事実の説明では重大度、結論、修正案を混ぜない。

### 2. リスク根拠

次の各項目を `確認済み`、`利用不可`、`定性的` のいずれかで記録する。根拠がない内容を推測で補わない。

- 変更範囲: ファイル、ディレクトリ、サブシステム、振る舞いの変化
- パス重要度: セキュリティ、永続化、金銭、共有境界など
- 履歴: churnや共変更。欠陥の証拠とは扱わない
- テスト有無: 関連テストと検証対象
- カバレッジ: 利用可能な場合のみ
- ロールバック: feature flag、復旧手順、不可逆変更

推奨深度:

- `Basic`: 狭く可逆で、十分にテストされ、重要経路を含まない
- `Standard`: 通常の既定値。重要な根拠が不足または不明確
- `Comprehensive`: 重要経路、広い影響、弱い検知、困難な復旧、重大な曖昧さがある

### 3. レビュー観点

依頼と変更内容に関係する観点だけを選ぶ。

- 機能: 仕様、成功・失敗経路、境界値、回帰、テスト
- 規約: リポジトリ規約、命名、型、責務、重複、保守性
- アクセシビリティ: キーボード、フォーカス、セマンティクス、ラベル、コントラスト、エラー表示
- セキュリティ: 認証・認可、入力境界、秘密情報、依存関係、解析、データ処理
- PR品質: 目的と差分の一致、スコープ、検証証跡、無関係な変更
- 準備状況: 競合、必須チェック、ドキュメント、移行、展開、ロールバック

各観点は同じ差分範囲を使う。並列サブエージェントを使う場合、差分範囲、リポジトリ規約、選択深度、安全規則を全エージェントへ渡す。

### 4. 重大度と判定

- `Critical`: データ損失、権限昇格、安全なリリースを妨げる重大障害
- `High`: 利用者影響や重大な回帰につながる可能性が高い問題
- `Medium`: 直ちにブロックしないが対応すべき問題
- `Low`: 軽微な明確性、品質、保守性の問題

`Critical` または `High` があれば `request_changes`、`Medium` または `Low` のみなら `approve_with_comments`、指摘なしなら `approve` とする。

### 5. 出力

指摘を重大度順に提示し、各項目に次を含める。

- タイトルと重大度
- ファイルと行
- 根拠となる差分または仕様
- 実害が生じる条件
- 最小限の修正方針

最後に前提、未確認事項、テスト不足、最終判定を短くまとめる。指摘がなければ明記し、残存リスクを示す。レポート保存はユーザーが明示した場合だけ、ワークスペース内の合意済みパスへ行う。

## 出典と変更

Microsoft `hve-core` の Code Review Skillを上記コミットに固定して日本語化・単体化した。原版が前提とする専用オーケストレーター、追跡用manifest、免責文書、PR投稿機能はこのワークスペースに存在しないため必須依存から除外した。外部投稿と永続化を既定動作から外し、秘密情報、外部通信、Git参照の安全規則を追加した。
